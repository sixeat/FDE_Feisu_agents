# 阶段 0 长连接事件探针说明

`scripts/feishu_long_connection_probe.py` 是一次性本地验证工具，用于让飞书开放平台验证应用的长连接状态，并接收 `im.message.receive_v1` 事件。它不属于主产品运行时。

## 本机运行

先在飞书开放平台的“凭证与基础信息”中复制 App ID 和 App Secret，只在当前 PowerShell 会话设置：

```powershell
$env:FEISHU_APP_ID = '<本机填写>'
$env:FEISHU_APP_SECRET = '<本机填写>'
& 'D:\Temp\feishu-sdk-venv\Scripts\python.exe' `
  F:\Code_X\FDE学习\scripts\feishu_long_connection_probe.py
```

脚本只输出事件类型、内容长度以及远端标识的短哈希，不输出消息正文、完整 ID 或密钥。看到 `LONG_CONNECTION_PROBE_START` 后，保持终端运行。

默认情况下探针只接收事件，不回复消息。确认事件接收成功后，如需验证“接收 → 发送”链路，可以在同一个 PowerShell 会话额外设置：

```powershell
$env:FEISHU_PROBE_REPLY = '1'
```

重新启动探针后，用户发来新消息时，探针会通过消息回复接口发送固定文本“已收到测试消息（Phase0 探针回复）”。它不会调用模型、读取文档或创建任务；收到机器人自己产生的消息时会跳过，避免循环。

## 开放平台操作顺序

1. 回到“事件与回调 → 事件配置”；
2. 保持“使用长连接接收事件”；
3. 点击“验证”，确认长连接已建立；
4. 验证通过后，添加“接收消息”事件（`im.message.receive_v1`）；
5. 保存事件配置；
6. 在测试群中由测试用户主动 `@` 机器人发送一条无敏感内容的消息；
7. 终端只应出现事件元数据；启用 `FEISHU_PROBE_REPLY=1` 后还应出现 `PROBE_REPLY_RESULT: code=0`；
8. 按 Ctrl+C 停止探针。

如果“验证”仍失败，只记录脱敏错误码和页面提示，不要把 App Secret 或消息正文发到聊天。卡片动作回调属于另一条 HTTP 回调链路，本次先不配置。

事件列表出现 `im.message.receive_v1` 后，不要因为下方列出了“全部群消息”“私聊消息”或其他机器人消息权限就继续申请；那些是该事件可能支持的扩展范围，本轮只使用已经开通的“群组中用户 @机器人 消息”。
