# 项目总规划一页版

> 版本：2026-09-26  
> 用途：解决阶段名称、官方能力和自研范围混淆。本文是导航页，详细约束以计划书和进度记录为准。

## 一句话定位

本项目是一个运行在飞书之上的小型多 Agent 组织治理系统：复用飞书已有的会议纪要、消息、任务、OpenClaw/CLI 等能力，自研 Agent 的权限、审批、任务状态、审计、恢复、知识治理和 Skill 生命周期。

飞书官方 Agent 也可以作为外部专业 Agent 被我们的编排 Agent 调用，前提是它提供受支持的 API、MCP、A2A、工作流、事件或 CLI 入口。我们的系统负责调用边界、权限、审批和对账，不假定官方 Agent 一定开放接口。

## 先看系统边界

```text
飞书官方底座
  ├─ 用户、群聊、卡片、文档、任务
  ├─ 智能会议纪要（如果测试租户开放接口）
  ├─ OpenClaw 插件 / CLI（如果权限和审计边界满足）
  └─ aPaaS（作为官方能力基线，不重复做通用低代码）
                ↓
自研 Agent 控制平面（项目核心）
  ├─ 用户与个人助手绑定
  ├─ Agent/Runtime 路由
  ├─ 权限交集和 ToolPolicy
  ├─ 人工审批与审批版本绑定
  ├─ durable TaskRun、重试、对账和 UNKNOWN
  ├─ 审计日志和运维状态
  ├─ 知识来源、版本与冲突治理
  └─ Skill 审核、启用、回滚
                ↓
可替换执行器
  ├─ Hermes（优先验证）
  ├─ OpenClaw / 飞书 OpenClaw（后续候选）
  ├─ 飞书 CLI（工具执行候选）
  └─ 自有 Worker / LLM / ASR（按需接入）
```

其中，飞书官方 Agent 位于“外部 Agent 服务”位置：它可以提供会议理解或办公执行能力，但返回结果必须经过我们自己的控制平面。

## 三类范围

### 必须自研

- 控制平面和内部任务模型；
- Agent、Runtime、ToolPolicy 的权限交集；
- 高风险操作人工确认；
- TaskRun 持久化、幂等、失败和未知结果对账；
- 审计日志；
- 多 Agent 委托和治理；
- 后续的知识冲突和 Skill 生命周期。

### 优先复用

- 飞书用户身份、群聊、卡片、文档和任务；
- 飞书智能会议纪要作为会议内容输入；
- 飞书 OpenClaw 插件或 CLI 作为候选执行器；
- Hermes 作为候选通用 Runtime。

飞书中已经存在的官方助手、团队机器人和智能体也可以登记到我们的 Agent 注册表中。注册不等于已经可自动调用：只有具备 API、事件、工作流、MCP、A2A 或 CLI 入口的 Agent 才进入自动适配；只能在界面中聊天的 Agent 暂时标记为人工节点。

### 暂时不做

- 自己做通用会议纪要产品；
- 自己做通用聊天办公助手；
- 一开始同时接入 Hermes 和 OpenClaw；
- 一开始做本地 Agent；
- 把 Laya 放进权限或审批链路；
- Kubernetes、对外多租户和商店分发；
- 复杂 H5 和通用 aPaaS。

## 路线图

### M0：能力和官方产品核验（当前）

这就是当前对话中所说的“第一阶段”。不开发主产品，只验证：

- Hermes 或其他 Runtime 能否被外部受控调用；
- 飞书测试租户能否读取会议产物、接收回调、发送卡片、创建测试任务；
- 官方智能会议纪要是否有可用开放接口；
- 飞书官方 Agent 是否提供 API、MCP、A2A、工作流、事件或 CLI 调用入口；
- 测试租户现有 Agent/机器人能否登记能力、范围、调用入口和责任人；
- 授权音频的 ASR 质量是否值得保留；
- Laya 是否有低风险决策收益。

出口：每项都有版本、权限、结果、证据和降级方案。当前被真实飞书租户和授权样本阻塞。

### M1：最小控制平面（计划书阶段 1）

先不用真实模型和真实写入，使用假 Runtime、假飞书工具和测试数据实现并测试：

```text
Actor → PersonalAssistant → Delegation → TaskRun
                                  ↓
                         Policy → Approval → ToolGateway → Audit
```

必须验证：越权被拒绝、旧审批失效、重复回调不重复执行、失败可恢复、未知结果进入对账。

### M2：会议结果落实闭环

优先使用飞书智能会议纪要或文字产物作为输入；自有 ASR 作为另一条输入路径：

```text
会议产物/录音
→ 待办提取
→ 责任人和范围检查
→ 飞书卡片人工确认
→ 创建飞书任务
→ 通知、审计、对账
```

这一阶段证明的是“安全落实”，不是“摘要比官方更好”。

如果官方会议 Agent 有结构化调用接口，优先采用“官方 Agent 产出 + 我们治理落实”的组合；如果只有消息或工作流入口，先做异步适配；如果只能网页人工操作，不做自动化模拟。

### M3：可靠性与部署

加入限流、重试、outbox、重启恢复、任务对账、Docker Compose 和演示故障场景。

### M4：个人助手和组织治理

加入多成员个人助手、共享 Agent、Agent 审核官、运维官、版本启停和告警。

### M5：知识与 Skill

加入混合检索、知识声明、版本、冲突候选、引用回答、Skill 生成、人工审核和回滚。

### 可选扩展

本地 Agent、OpenClaw 第二 Runtime、A2A、Laya、完整 H5 工作台，只有在主线稳定后再选一到两个作为加分项。
