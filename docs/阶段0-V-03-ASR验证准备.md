# 阶段 0 / V-03：会议语音转写验证准备

> 当前状态：候选方案已锁定，待授权音频样本和真实转写验证；尚未把任何录音上传到外部服务。

## 1. 验证目标

确认会议 Agent 的第一步能否稳定得到可人工复核的转录文本，并回答：

- 中文普通话、多人讨论和重叠发言的可读性如何；
- 是否有可用时间戳，能回指原始音频；
- 说话人标签是否足以辅助责任人候选；
- 处理时延、文件大小限制、失败重试和费用是否能接受；
- 音频和转录文本的保留、删除及脱敏边界是什么。

## 2. 最小样本集

至少准备四类获得明确授权的样本，使用虚构项目内容或已脱敏内容：

1. 清晰单人讲话；
2. 两人或多人轮流发言；
3. 噪声、重叠或远场收音；
4. 含含糊日期、责任人和截止时间的会议片段。

每个样本只记录格式、时长、大小、语言和授权范围，不把原始音频提交到仓库。

## 3. 对比方法

至少保留一个可替换的基线：

- 当前选定的云端 ASR API；
- 本地或自托管 Whisper/faster-whisper 类方案（资源允许时）。

比较字段为：字错误率的人工近似、时间戳覆盖、说话人标签、待办字段可抽取率、延迟、费用和失败类型。

会议主线只要求“转录文本支持人工复核”。说话人标签不能直接等同于飞书成员身份，责任人匹配必须进入结构化抽取和人工确认。

## 4. 通过标准与降级

通过条件：清晰样本和多人样本能提供可读文本；待办原文可以回指；失败和超时可识别；不会把未经确认的说话人直接写成任务责任人。

未通过时，会议主线降级为用户上传已有文字纪要，或只生成待人工整理的转录草稿，不阻塞控制平面和飞书权限验证。

## 5. 待补资源

- 取得参会人和录音所有人的授权；
- 选定一项 ASR 服务或本地模型；
- 确认音频保留期和删除方式；
- 确认是否允许使用说话人分离。

选择它作为首个基线的原因是依赖规模相对可控、适合服务器 CPU/GPU 运行，并且可以在实验中记录分段/词级时间戳。它本身不解决说话人身份与飞书成员匹配，也不应直接把说话人标签写入任务责任人。

### 保留比较项：FunASR

`funasr==1.4.16` 的 Python 包声明为 MIT，面向中文语音场景并提供较完整的语音处理组件；但依赖 `torch`、ModelScope、Transformers、音频和训练相关包较多，模型与标注资源的许可仍需单独确认。因此暂不同时安装，只有首选基线在中文多人或噪声样本上明显不足时再建立比较环境。

### 本次边界

- 只下载了 `faster-whisper` 的 Python wheel 做元数据预检，没有安装依赖，也没有下载模型权重。
- 当前工作区没有音频样本，不能得出中文准确率、多人分离、延迟或费用结论。
- 通过标准仍是“转录文本可人工复核，并能回指音频片段”；ASR 输出不会直接决定责任人或飞书写入。

### 获得样本后的固定实验顺序

```text
音频格式/授权检查
→ faster-whisper 固定模型转写
→ 保存脱敏转录、段/词时间戳和耗时
→ 人工对照待办、日期和责任人原文
→ 记录多人/噪声/重叠失败
→ 决定是否引入 FunASR 比较
→ 确定转人工和文字纪要降级条件
```

在同一合成中文音频上补跑 `Systran/faster-whisper-base`（Hub revision `ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66`，模型卡片声明 MIT）：

这说明增大模型有改善，但合成音频不能用于决定最终质量阈值；服务器 CPU 资源和真实会议噪声下的表现仍需测量。

### 结论

- **通过**：faster-whisper 的临时环境、模型下载、CPU `int8` 推理、音频读取、语言判断、分段和时间戳输出链路可运行。
- **未通过**：`tiny` 模型的中文质量不足以支撑会议闭环；没有多人、重叠、噪声、真实责任人和日期样本。
- **决策**：把 faster-whisper 保留为工程基线，`base` 作为当前最低对照，暂不固定最终模型；真实样本到位后比较更大 Whisper 模型和 FunASR，并测量端到端待办字段可抽取率。
- **降级**：质量不达标时只保留转录草稿，要求用户上传文字纪要或人工修订后才进入任务提取；不自动写入责任人。
