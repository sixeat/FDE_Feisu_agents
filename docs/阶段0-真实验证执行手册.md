# 阶段 0 真实验证执行手册

> 用途：测试租户和专用会议产物到位后，按固定顺序完成阶段 0 的真实证据收集。执行手册不保存密钥、完整文档正文或群消息。

## 1. 开始前的安全检查

在本机建立未跟踪的临时环境变量或密码管理器条目，不把值复制到聊天、Markdown、日志或 Git：

```text
FEISHU_APP_ID
FEISHU_APP_SECRET
FEISHU_ENCRYPT_KEY
FEISHU_VERIFICATION_TOKEN
FEISHU_TEST_CHAT_ID
FEISHU_TEST_DOCUMENT_ID
FEISHU_TEST_FILE_TOKEN
```

执行机器只使用测试租户和测试资源。日志只保留身份类型、接口、scope 类别、HTTP 状态、脱敏错误码和远端 ID 的哈希或末尾片段。

## 2. 飞书测试租户准备

在开放平台创建企业自建应用，并按租户当前页面名称开启：

1. 机器人能力；
2. 事件订阅和回调配置；
3. 卡片动作回调；
4. 网页应用能力（本阶段只需确认能配置，不要求实现 H5）。

权限申请从最小范围开始：

```text
机器人接收群内 @事件和发送消息/卡片
读取专用测试文档和文件
创建、查询专用测试任务
读取触发用户身份
```

不申请读取全部群消息。不在第一轮申请文档删除、批量知识库写入或其他高风险写权限。具体 scope 名称以目标租户页面和官方接口文档为准，记录实际名称与审批结果。

准备以下资源：

```text
测试用户 A       触发任务
测试用户 B       接收任务/参与回调
测试管理员       执行人工确认
测试群           只加入 A、B 和机器人
测试文档/文件    虚构会议纪要，内容不含个人信息
测试任务空间     可删除或归档
```

## 3. 回调地址和验真顺序

回调地址必须只暴露本地测试服务，并记录隧道过期时间。服务入口按以下顺序处理：

```text
读取原始 body
→ 检查 timestamp / nonce / signature 是否齐全
→ 校验签名和 verification token
→ 处理 challenge 或事件
→ 以 event_id 去重
→ 先写入内部事件台账
→ 异步执行后续读取/审批
```

缺少请求头、签名不符、token 不符都应直接拒绝并记录原因，不能把 SDK 的异常 500 当成可重试的业务失败。重复事件必须返回已有处理结果或安全确认，不能重复创建任务。

## 4. V-02 实际执行顺序

### 4.1 只读文件

用触发用户身份和应用身份各执行一次读取，使用同一个专用测试文档/文件：

```text
记录：身份类型、scope 类别、HTTP 状态、文档/文件 ID 哈希、正文长度
检查：用户看得到的资源是否可读；用户看不到的资源是否被拒绝
```

正文不写入仓库。若应用身份能读取触发用户看不到的内容，立即停止后续实验并调整权限模型。

### 4.2 卡片回调

机器人发送一张只有“确认测试任务”按钮的卡片。分别测试：

- 有权限的管理员点击一次；
- 无确认权用户点击一次；
- 同一回调重复发送；
- 修改动作内容后使用旧回调。

验收：无权限、重复或过期回调不能创建任务；每次结果都有审计记录。

### 4.3 测试任务和对账

管理员确认后，只创建一条可删除的测试任务，并保存：

```text
本地 task_run_id
审批记录版本
远端任务 ID（哈希或末尾片段）
请求身份类型
HTTP 状态和脱敏响应摘要
查询结果与查询时间
```

故意重复确认一次，验证幂等键不会创建第二条任务。若请求超时，不能直接重试写入；先查询或标记 `UNKNOWN`，再决定对账或转人工。

## 5. V-06 飞书会议产物验证

准备一个专用会议纪要/转写文档，按以下顺序执行：

1. 应用身份读取文档元信息和根块，记录版本号、块数量、文本长度和文档 ID 短哈希；
2. 解析标题、段落、列表和表格，确认每条待办能保留原文块或来源位置；
3. 检查文档版本变化能否被识别，旧结果不能直接覆盖新结果；
4. 在有条件时验证无权用户或撤权后的读取拒绝；
5. 只读验证完成后，才将结构化结果接入卡片审批和任务写入探针。

手工创建的飞书文档只能证明读取和解析链路。只有真实飞书会议纪要/转写产物才能证明官方会议产物接口。

## 6. 证据归档和阶段评审

每个实验结束后只归档以下内容：

```text
版本和模型 revision
scope 类别和身份类型
脱敏请求/响应摘要
HTTP 状态和错误分类
远端资源 ID 的哈希/末尾片段
输入样本的哈希、格式、时长和授权范围
结果统计、失败案例类别和降级决定
```

阶段 0 评审必须逐项更新 `docs/阶段0-出口评审.md`。只有飞书真实事件、文件权限、任务创建/对账和会议产物读取都有独立证据，才把相关出口标记为通过；否则保持“进行中”，并记录下一步和责任人。V-03 ASR 属于后置扩展，不是第一版出口条件。
