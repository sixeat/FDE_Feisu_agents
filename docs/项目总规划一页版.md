# 项目总规划一页版

> 版本：2026-11-10（成员来源证据预览与真实授权边界，飞书内教研验证）
>
> 用途：导航教研目标、既有会议试点和正式阶段编号。项目当前状态只以进度记录为准；详细约束以计划书为准。

## 一句话定位

本项目建设 Agent 生态全生命周期系统：从授权协作记录中每日发现流程机会，经架构、构建、评测、审核发布、运行、运维改进，直至回退或退役。Super Agent 协调架构师、审核官、运维官和业务 Agent，在逐级授权的自治范围内推动完整流程。控制平面负责权限、版本、发布和审计。当前以飞书为唯一协作平台，以高校课程组教研为目标场景；既有会议试点作为另一类 Agent 生命周期样本保留。

飞书官方 Agent 可以作为外部专业 Agent 的候选，前提是存在受支持的 API、MCP、A2A、工作流、事件或 CLI 入口。未来若单独启动第二教学平台扩展，须另验其真实授权、接口、版本与撤权；当前路线不依赖它。

## 先看系统边界

```text
飞书官方底座
  ├─ 用户、群聊、卡片、文档、任务
  ├─ 课程文档、备课资料、任务与教研会议纪要
  ├─ OpenClaw 插件 / CLI（如果权限和审计边界满足）
  └─ aPaaS（作为官方能力基线，不重复做通用低代码）
                ↓
自研 Agent 控制平面（项目核心）
  ├─ 用户与个人助手绑定
  ├─ 成员授权来源与每日流程发现
  ├─ Super Agent 编排架构师/审核官/运维官
  ├─ Agent/Runtime 路由
  ├─ 权限交集和 ToolPolicy
  ├─ 人工审批与审批版本绑定
  ├─ durable TaskRun、重试、对账和 UNKNOWN
  ├─ 持久事件、去重与治理事项队列
  ├─ 自治等级、额度和升级条件
  ├─ 审计日志和运维状态
  ├─ 知识来源、版本与冲突治理
  └─ Skill 审核、启用、回滚
                ↓
教学来源与可替换执行器
  ├─ 飞书文档的成员授权只读来源
  ├─ Hermes（优先验证）
  ├─ OpenClaw / 飞书 OpenClaw（后续候选）
  ├─ 飞书 CLI（工具执行候选）
  └─ 自有 Worker / LLM（按需接入）
```

成员个人助手可提供交互入口和数据隔离；生态 Super Agent 负责流程发现与 Agent 团队协调，架构师、审核官、运维官执行专门职责。专业 Agent 在受限契约中工作；控制平面是权限、版本、自治策略、运行状态和外部副作用的权威。聊天分析只处理成员明确授权的来源；撤权后停止读取。事件和日批次会产生可追溯机会或治理事项，不会绕过评测发布门槛。飞书官方 Agent 位于“外部 Agent 服务”位置，其结果也须经过本系统的来源、权限与审批门。

## 三类范围

### 必须自研

- 控制平面和内部任务模型；
- Agent、Runtime、ToolPolicy 的权限交集；
- 高风险操作人工确认；
- TaskRun 持久化、幂等、失败和未知结果对账；
- 审计日志；
- 多 Agent 委托和治理；
- 后续的知识冲突和 Skill 生命周期。

### 优先复用

- 飞书用户身份、群聊、卡片、文档和任务；
- 飞书文档和虚构或脱敏样本作为教研输入；现有智能会议纪要可用于教研会议；
- 飞书 OpenClaw 插件或 CLI 作为候选执行器；
- Hermes 作为候选通用 Runtime。

飞书中已经存在的官方助手、团队机器人和智能体也可以登记到我们的 Agent 注册表中。注册不等于已经可自动调用：只有具备 API、事件、工作流、MCP、A2A 或 CLI 入口的 Agent 才进入自动适配；只能在界面中聊天的 Agent 暂时标记为人工节点。

### 暂时不做

- 自己做通用会议纪要产品；
- 自己做通用聊天办公助手；
- 自动评分、学生个体画像和未授权的教学平台抓取；
- 一开始同时接入 Hermes 和 OpenClaw；
- 一开始做本地 Agent；
- 把 Laya 放进权限或审批链路；
- Kubernetes、对外多租户和商店分发；
- 复杂 H5 和通用 aPaaS。

## 路线图

### 开发主线：Agent 生态全生命周期

```text
成员授权聊天/任务来源
→ 每日观察并发现可智能化流程
→ 形成、合并或放弃流程机会
→ Super Agent 编排架构师、审核官、运维官
→ Agent / Skill 架构和构建
→ 独立评测、授权、审核发布
→ 灰度、运行、监控和事件处置
→ 版本改进、复用、回退或退役
```

流程机会生命周期、单个 Agent/Skill 版本生命周期和运行任务生命周期嵌套在同一生态全生命周期中。每一步都要回答：谁能操作、依据哪个版本、产生什么不可变证据、失败后如何恢复，以及当前自治等级允许哪些动作。会议任务与课程教研是其中的业务样本；阶段 0～8 的编号保留用于追踪历史工作包，当前优先级按完整生命周期中尚未完成的环节确定。

### M0：既有能力和官方产品核验（计划书阶段 0）

这是会议试点形成时的能力验证范围；实际完成与未验收项以进度记录为准：

- Hermes 或其他 Runtime 能否被外部受控调用；
- 飞书测试租户能否读取会议产物、接收回调、发送卡片、创建测试任务；
- 官方智能会议纪要是否有可用开放接口；
- 飞书官方 Agent 是否提供 API、MCP、A2A、工作流、事件或 CLI 调用入口；
- 测试租户现有 Agent/机器人能否登记能力、范围、调用入口和责任人；
- 授权音频 ASR 的历史试探；该能力已退出第一版范围；
- Laya 是否有低风险决策收益。

出口：每项都有版本、权限、结果、证据和降级方案。教研转向不追溯改写 M0 证据；T-05 第二教学平台延期且不阻塞当前交付。

### M1：最小控制平面（计划书阶段 1）

原阶段使用假 Runtime、假飞书工具和测试数据验证：

```text
Actor → PersonalAssistant → Delegation → TaskRun
                                  ↓
                         Policy → Approval → ToolGateway → Audit
```

必须验证：越权被拒绝、旧审批失效、重复回调不重复执行、失败可恢复、未知结果进入对账。

### M2：既有会议结果落实试点（计划书阶段 2）

既有试点使用飞书会议纪要或文字产物作为输入：

```text
会议产物/录音
→ 待办提取
→ 责任人和范围检查
→ 飞书卡片人工确认
→ 创建飞书任务
→ 通知、审计、对账
```

这一阶段证明会议任务的安全落实，不等于课程计划对齐或集体备课已通过。自有 ASR 已退出第一版范围。

如果官方会议 Agent 有结构化调用接口，优先采用“官方 Agent 产出 + 我们治理落实”的组合；如果只有消息或工作流入口，先做异步适配；如果只能网页人工操作，不做自动化模拟。

### M3：既有可靠性与部署（计划书阶段 3）

本阶段验收要求：Runtime 任务具有持久领取与租约；运行结果在进程中断后可恢复，缺少确定结果时进入待核验且不得盲目重跑；成员可查询运行状态。需要覆盖并发领取、调用前后中断、响应丢失和权限撤销。实现与各环境验收状态以进度记录为准；结果未知先核对或人工处置，业务转向不自动打开线上消息、正式草稿卡片或任务持续写入。

### M4：课程组协作、典型 Agent 和组织治理（计划书阶段 4～5）

受管 Agent 的运行失败、灰度评审失败和审批到期已在本地形成审核官可认领的内部只读治理事项；管理员保留完整审计与成员管理。治理队列的持久性、并发处置和权限边界已通过本地测试。授权教学来源的版本/内容差异也已形成无正文的不可变诊断证据，由课程负责人确认业务影响；审定会复查来源是否仍处于诊断版本，不会自动更新来源或触发任务。下一步用获授权的样例课程和教师验收登记、共享、诊断、审定，再做课程计划对齐及集体备课建议；本地虚构样本测试不替代教学业务验收。

### M5：教学反馈、自定义 Agent 与 Skill（计划书阶段 6～7）

在飞书内做脱敏汇总反馈复盘、课程知识引用与冲突复核。两类典型任务通过后，教师可提交自定义 Agent/Skill 草稿，经过独立评测、课程负责人和管理员双确认、建议灰度、回退与归档。第二平台只读适配是未来独立扩展。

### 阶段 8：教研工作台与交付

H5 展示课程来源、差异和备课建议、人工审核、版本、运行、Skill 与审计；演示两类典型任务、一次反馈复盘、一个自定义 Agent、飞书来源的授权与撤权、越权拒绝、失败对账和回退。实际状态及真实指标只从进度记录和验收报告引用。

### 可选扩展

第二教学平台、本地 Agent、OpenClaw 第二 Runtime、A2A 和 Laya，只有在教研主线稳定后再选作扩展。学生个体数据和自动评分不进入第一轮。

## 当前下一步

人工主导的通用 Agent 生命周期已有本地 API 与真实浏览器合成演练，Runtime 持久领取/快照恢复和审核官队列通过本地测试。A1 流程发现已有本地只读原型：成员订阅本人可访问的群聊/单聊，手动扫描最近 24 小时的重复文本，按需临时预览匹配证据，人工采纳后生成关联的 Agent 草稿；群聊和单聊的合成浏览器流程均已通过。预览只返回本人候选最近 24 小时内最多 3 条、每条至多 200 字的匹配摘录；读取说明升级到 v2，旧订阅需本人续认。来源撤销会阻断衍生草稿发布；若已发布 Agent 的当前版本受影响，则形成审核官可认领的本地运维事项，不自动暂停。应用侧聊天权限与 OAuth 请求 scope 已核对，但真实成员 OAuth 及飞书读取尚未验收；公网工作台当前还受备案接入异常阻断。语义级发现、系统级 Super Agent、后台每日调度和 A0–A3 执行策略尚未验收；当前全量测试以进度记录最新结果为准：

1. 核实公网工作台的备案接入状态，成员重新完成 OAuth 授权；用本人有权访问的群/单聊分别验收指定会话读取与撤权；
2. 用获授权测试会话验证候选准确性、证据预览和误报边界，再扩展到跨日重复；
3. 评估合法的持续 OAuth 授权与刷新机制后，才实现后台日批次；
4. 再实现生态 Super Agent 持久编排，让架构师/审核官/运维官处理机会和治理事项，并逐步验收更高自治级。

跨平台接入当前延期，不作为阶段 6/8 或 D-01 的验收阻塞。线上消息入口、正式 Card 草稿审核和飞书任务持续写入保持原关闭状态，只有独立安全验收后才讨论开启。
