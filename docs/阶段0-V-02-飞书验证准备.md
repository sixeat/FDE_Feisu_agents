# 阶段 0 / V-02：飞书能力验证准备

> 当前状态：待外部测试资源；本文件只定义实验边界，不代表飞书接口已经验证通过。

## 1. 目标

在一个专门的飞书测试企业自建应用和测试群中，验证会议主线所需的最小能力：

```text
测试用户/机器人事件
→ 读取一个专用测试文件
→ 发送测试卡片
→ 接收并验真一次卡片回调
→ 人工确认后创建一个测试任务
→ 保存远端资源 ID 并查询/对账
```

所有资源都必须是测试资源。实验不读取全量群消息，不修改正式文档，不创建真实业务任务。

### 1.3 合成回调处理探针（不连接飞书）

在 `D:\Temp\feishu-sdk-venv` 中使用虚构的 `encrypt_key`、`verification_token` 和合成 JSON，构造 `RawRequest` 交给 `EventDispatcherHandler`：

```text
challenge             → HTTP 200，返回 challenge
正确签名 + 正确 token  → HTTP 200，回调处理器收到 event_id 和 event
错误签名              → HTTP 500，返回 signature verification failed
错误 verification_token → HTTP 500，返回 invalid verification_token
```

这证明 SDK 的本地处理分支可以按预期被驱动，但不代表飞书真实事件已经到达。另一个合成请求在完全缺少时间戳和 nonce 时触发了 `TypeError`，SDK 返回 HTTP 500 而不是结构化的签名拒绝。控制平面因此必须在调用 SDK 前检查请求头完整性，并统一转换为不泄露堆栈的拒绝响应；不能把 SDK 的异常状态直接当作业务事件失败或重试信号。

## 2. 不在文档或仓库保存的内容

- `App Secret`、`tenant_access_token`、`user_access_token`、OAuth refresh token；
- 含个人信息的录音、文档正文或群消息；
- 未脱敏的请求头、回调签名和响应体。

密钥只在本地未跟踪的环境变量或密码管理器中使用。记录中只保留 scope、身份类型、资源类型、HTTP 状态、脱敏错误码和远端资源 ID 的哈希或末尾片段。

## 4. 需要确认的权限类别

最终 scope 以目标租户开放平台页面和接口文档为准，不能仅凭计划书中的名称推断已获批。实验至少记录以下类别：

- 机器人接收群内 @事件和发送卡片消息；
- 读取专用云文档/文件；
- 创建测试任务和查询任务状态；
- 读取触发任务用户的身份信息；
- 卡片回调验真所需的事件订阅配置。

不申请读取全部群消息的权限。文档写入、任务修改等能力只有在读、回调和审批链路验证后再单独申请。

## 6. 通过标准

V-02 只有在下面各项都有独立证据时才算通过：

1. 能解释应用身份和触发用户身份各自能访问什么；
2. 能读取专用测试文件并保留最小化证据；
3. 能发送卡片并验真一次回调；
4. 人工确认之前不会创建或修改任务；
5. 人工确认之后能创建测试任务，保存远端 ID，并通过查询或对账确认结果；
6. 失败、超时和重复回调不会被写成成功；
7. 明确最小 scope、降级方式和无法实现的接口边界。
