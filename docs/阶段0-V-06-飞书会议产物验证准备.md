# 阶段 0 / V-06：飞书会议产物接入验证准备

> 当前状态：待验证。本文只定义实验边界，不代表飞书会议产物接口已经通过。

## 1. 目标

确认第一版能否直接读取飞书已经生成的会议纪要、会议转写或相关文档，并把它们作为会议 Agent 的输入。项目不实现录音、自动入会、语音识别或说话人分离。

## 2. 最小测试资源

| 资源 | 要求 |
|---|---|
| 专用会议文档 | 只包含虚构会议内容，不含个人隐私或真实业务机密 |
| 会议内容 | 至少包含一个明确待办、一个缺少责任人的事项、一个含糊日期和一个决定事项 |
| 测试用户 | 文档创建者、触发机器人用户；如能区分，再准备无权用户 |
| 文档链接/ID | 只在本机环境变量中使用，日志只保留短哈希 |

如果暂时拿不到飞书会议自动生成的纪要，可以先用手工创建的飞书文档模拟其结构；模拟结果只能证明文档读取和解析链路，不能宣称已经验证飞书会议产品的自动产物接口。

## 3. 验证顺序

1. 使用应用身份读取专用文档元信息和根块，记录返回码、版本号、块数量、文本长度和文档 ID 短哈希。
2. 确认文档来源链接、版本或更新时间可以进入 `MeetingRecord` 的来源字段。
3. 解析文档块，检查标题、段落、列表和表格是否能保留来源位置。
4. 用固定的虚构会议文本生成结构化结果：摘要、决定、待办、责任人候选、截止时间候选和待补充原因。
5. 验证无权用户或撤权后的读取行为；拒绝时不能把缓存正文交给模型或用户。
6. 只读验证通过后，才把结构化结果接到现有卡片审批和任务写入探针；本验证本身不创建任务。

## 4. 通过条件

- 应用身份能读取专用会议文档；
- 每条待办能引用原文块或稳定来源位置；
- 文档版本发生变化时能识别新旧版本，旧结果不能直接覆盖新结果；
- 缺少责任人、截止时间或会议范围时进入待补充状态；
- 权限拒绝、文档不存在和解析失败均可见且不触发写入；
- 读取日志不保存完整正文、令牌或个人身份原文。

## 5. 降级路径

如果官方会议产物没有稳定的可用接口，第一版允许用户提交文字纪要或在 H5 粘贴会议结果。控制平面、审批、权限交集、任务幂等和审计不因输入方式变化而改变。自研录音转写列为后置扩展，不为补齐 V-06 临时引入 ASR。

## 6. 不在本项验证的内容

- 录音采集、自动入会和实时转写；
- 说话人识别、声纹与成员自动绑定；
- 会议产品内部的生成质量；
- 真实业务文档批量索引或 RAG；
- 会议文档的自动修改和任务写入。
