## 已确定的设计决策

1. 现有 `fde-info-agent` 作为学习项目保留，主项目未来放在独立子目录。
2. 飞书承担交互、企业业务数据、身份和审批入口。
3. Hermes 是第一版优先接入的 Agent Runtime；OpenClaw 后置。Hermes 通过自研 `RuntimeAdapter` 接入，不能直接越过控制平面调用飞书。
4. 自研 Agent 组织管理系统承担控制平面和企业治理。
5. 第一条核心业务是读取飞书会议纪要/转写文档并落实为飞书任务。
6. 个人助手运行在服务器上，成员本地电脑只提供可选本地连接器。
7. 个人助手是成员统一入口，业务 Agent 负责专业流程。
8. 用户权限与 Agent 权限取交集。
9. 高风险写操作必须经过人工确认。
10. RAG 使用向量检索、关键词检索和元数据过滤，向量模型不负责最终冲突判断。
11. H5 是管理和治理工作台，不是第一条业务的主要入口。
12. 阶段 1 控制平面和阶段 2 飞书基础链路已经完成；阶段 0 核心能力有实测证据但仍有未验收边界。当前处于阶段 3，Hermes 会议语义执行及真实人工审批已通过，继续补齐任务执行可靠性。
13. 计划书已增加功能编号（V/C/M/R/P/G/K/S/H/D/X）、依赖、关键验收场景和降级条件；这些是目标清单，不代表完成。
14. 飞书官方能力作为底座和对照，不重复实现通用会议纪要、通用个人助手、CLI 或低代码应用平台；自研重点是多 Agent 治理和会议结果落实闭环。
15. 个人助手负责理解需求、受控委托、持续跟进与每日整合消息；业务 Agent 可经控制平面直接互相委托。成员自选关注来源，记忆在授权工作范围内被动形成，成员保留查看、纠错和删除权。
16. Agent 准入与正式版本转正由领域负责人确认业务质量、管理员确认系统权限及发布范围；知识冲突由文档创建者和领域负责人双确认，同一人兼任时只需一次。治理 Agent 不自审自批，也不替业务人员决定任务归属。
17. 官方用户身份消息历史/搜索接口存在高级权限路径，但当前租户未授权或实测；目标版不依赖默认旁听全部成员聊天。云文档事件订阅另要求订阅者具备拥有者或管理者权限。
18. 复用从当前控制平面出发：持久化 worker、租约和写前预检已补齐，下一步再验证 Promptfoo 离线评测；新增配置与输出契约渐进使用已有 Pydantic，运维阶段候选 APScheduler 稳定 3.x 单实例。整体平台、额外身份服务与队列迁移后置。候选只完成研究，不代表已接入；依据见计划书第 21.2～21.6 节。
