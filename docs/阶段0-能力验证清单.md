# 阶段 0：能力验证清单

> 目标：验证项目的关键外部依赖和核心决策假设。
>
> 当前状态：进行中；只做小型验证，不开始主产品开发。
>
> 关联计划：`docs/FDE-Agent-组织管理系统-计划书.md` 的 V-01～V-04。

## 1. 本阶段的边界

本阶段只回答“能不能接、怎么接、是否值得接”，不实现完整的个人助手、Agent 组织管理、H5 或会议业务闭环。

允许产出：

- 版本和许可证记录；
- 脱敏的接口调用记录；
- 小型样本的转录和决策评估；
- 接入结论、风险清单和降级方案；
- 可以删除或替换的实验脚本。

暂不做：

- 真实生产数据批量处理；
- 自动创建真实任务；
- 对外部署或多租户；
- 同时接入 Hermes 和 OpenClaw；
- 把 Laya 直接放进安全阻断链路；
- 把任何参考项目复制进主项目。

## 2. 验证顺序

```text
V-01 Runtime 能力
  → V-02 飞书资源和身份能力
  → V-03 语音转写能力
  → V-04 Laya 决策能力
  → 阶段 0 评审
```

V-01～V-04 可以分别失败。一个验证失败不代表项目失败，必须记录替代方案和对范围的影响。

## 3. V-01：Runtime 能力

### 要回答的问题

- Hermes 是否有稳定的外部调用入口？
- 能否注入受控工具，而不是让 Runtime 自由访问飞书凭证？
- 能否返回结构化结果和执行轨迹？
- 任务等待人工审批时，能否释放进程并在回调后恢复？
- 会话、记忆、工作目录和凭证是否真正隔离？
- 是否需要把 OpenClaw 暂时降级为参考，不做第二 Runtime？

### 最小实验

```text
固定输入
→ Runtime 执行一个无副作用的分类任务
→ 调用一个本地假工具
→ 返回结构化结果和轨迹
→ 重启或结束执行
→ 检查状态是否可恢复
```

### 通过条件

- 不需要把飞书 token 放进模型或 Runtime 环境；
- 工具调用可以被控制平面拦截；
- 结果和错误可被外部读取；
- 失败时能明确说明是接口不支持、权限问题还是实现限制。

## 4. V-02：飞书能力

### 要回答的问题

- 目标租户如何提交或获取会议录音文件？
- 文件下载需要哪种身份和 scope？
- 机器人事件、卡片回调和 H5 登录分别如何验真？
- 任务创建使用应用身份还是触发用户身份？
- 飞书任务接口是否支持查询或辅助对账？
- 最小权限是否足够完成演示？

### 最小实验

```text
测试应用和测试用户
→ 读取一个专门创建的测试文件
→ 发送一张测试卡片
→ 接收并验证一次回调
→ 在人工确认后创建一个测试任务
→ 查询或保存远端任务标识
```

所有写入都使用测试资源，操作前人工确认，保存脱敏请求和响应。不能把测试成功推导成生产权限已经完备。

## 5. V-03：语音转写能力

准备少量获得授权的会议样本，至少包含：清晰单人、多人讨论、噪声或重叠发言、含糊日期和未明确责任人。

记录：

- 音频格式、时长和大小；
- 转录文本可读性；
- 时间戳是否能回指原音频；
- 说话人标签是否稳定；
- 失败、超时和费用；
- 模型版本和请求参数。

第一阶段只要求转录文本能支持人工复核。说话人标签不直接当作飞书成员身份，责任人仍由结构化抽取和人工确认决定。

## 6. V-04：Laya 决策能力

Laya 只验证低风险的结构化决策：

```text
路由：会议 / 文档 / 任务 / 知识
补问：责任人 / 截止时间 / 可见范围是否缺失
候选：低风险 / 需要审批 / 信息不足
```

建立人工标注的小样本，并和两个基线比较：

1. 确定性规则；
2. 当前使用的 LLM 结构化输出。

记录模型和权重版本、问题 schema、输入长度、概率校准、延迟、错误案例和转人工率。未通过时，会议主线继续使用规则与 LLM，不影响项目。
