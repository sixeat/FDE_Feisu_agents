# 阶段 0 / V-04：Laya 决策模型验证准备

> 当前状态：部分通过（完成无权重静态与路由验证，真实权重和业务样本仍待验证）。

## 1. 验证边界

Laya 只作为低风险 Decision Layer 候选，输入已经结构化的任务上下文，输出路由、补问或风险候选。它不负责转录、最终权限判断、人工审批结论或飞书写入。

允许验证的任务：

- 会议 / 文档 / 任务 / 知识路由；
- 缺少责任人、截止时间或可见范围时的补问候选；
- 低风险、需要审批、信息不足的候选分类；
- 运维错误类别候选。

## 2. 小样本与基线

建立人工标注的小样本，每条输入包含结构化字段、标签、标注理由和是否应转人工。使用两个基线对照：

1. 确定性规则；
2. 当前 LLM 的结构化输出。

记录 Laya 仓库 commit/tag、模型权重版本、许可证、问题 schema、输入长度、延迟、资源占用、置信度校准和错误案例。

## 3. 通过标准

Laya 只有在低风险路由和补问任务上相对基线有稳定收益，且错误时能回退到规则或人工，才考虑作为可选组件。模型输出必须进入规则引擎，不能直接改变权限、审批状态或工具调用。

## 4. 降级路径

权重不可得、中文效果不稳定、资源占用过高或概率不可靠时，使用规则 + LLM 结构化输出；会议闭环和治理安全边界不依赖 Laya。

## 5. 待补资源

- 确认 CPU/GPU 资源和可接受延迟；
- 复核代码与模型权重许可证是否分别满足使用条件。

### 当前结论

- **已证明**：Laya 0.3.20 的源码可编译；`Router.route` 是不加载权重的纯路由路径；路由优先级、语言提示和 CLI 契约的无权重测试通过。
- **尚未证明**：中文会议样本的决策准确率、补问/风险分类收益、概率校准、真实推理延迟、CPU/GPU 资源占用和模型权重许可证。
- **架构影响**：可以把 Laya 作为可选的低风险路由候选层继续设计，但不能把本次结果写成“Laya 已可用于会议决策”，也不能让它改变权限、审批或飞书写入。
- **降级路径**：真实权重或中文样本验证不通过时，使用确定性规则 + LLM 结构化输出，Laya 从运行链路移除。
