# 项目总规划一页版

> 版本：2026-10-20（教研场景转向）
>
> 用途：导航教研目标、既有会议试点和正式阶段编号。详细约束以原计划书和进度记录为准。

## 一句话定位

本项目面向高校课程组教研，建设以飞书为协作入口、以一个经授权教学平台为第二只读来源的多 Agent 编排与治理系统；自研权限、审批、任务状态、审计、恢复、不可变版本和 Skill 生命周期。既有“会议纪要转飞书任务”保留为可复用试点，不算教研场景已验收。

飞书官方 Agent 可以作为外部专业 Agent 的候选，前提是存在受支持的 API、MCP、A2A、工作流、事件或 CLI 入口。教学平台也须有授权与接口/导出证据；人工导出文件只证明跨来源输入，不等于在线跨平台接入。

## 先看系统边界

```text
飞书官方底座
  ├─ 用户、群聊、卡片、文档、任务
  ├─ 课程文档、备课资料、任务与教研会议纪要
  ├─ OpenClaw 插件 / CLI（如果权限和审计边界满足）
  └─ aPaaS（作为官方能力基线，不重复做通用低代码）
                ↓
自研 Agent 控制平面（项目核心）
  ├─ 用户与个人助手绑定
  ├─ Agent/Runtime 路由
  ├─ 权限交集和 ToolPolicy
  ├─ 人工审批与审批版本绑定
  ├─ durable TaskRun、重试、对账和 UNKNOWN
  ├─ 审计日志和运维状态
  ├─ 知识来源、版本与冲突治理
  └─ Skill 审核、启用、回滚
                ↓
教学来源与可替换执行器
  ├─ 第二教学平台的授权只读适配器（待选型和验证）
  ├─ Hermes（优先验证）
  ├─ OpenClaw / 飞书 OpenClaw（后续候选）
  ├─ 飞书 CLI（工具执行候选）
  └─ 自有 Worker / LLM（按需接入）
```

其中，飞书官方 Agent 位于“外部 Agent 服务”位置；其返回结果必须经过本系统的来源、权限与审批门。第二教学平台的只读适配也不能替代课程范围授权。

## 三类范围

### 必须自研

- 控制平面和内部任务模型；
- Agent、Runtime、ToolPolicy 的权限交集；
- 高风险操作人工确认；
- TaskRun 持久化、幂等、失败和未知结果对账；
- 审计日志；
- 多 Agent 委托和治理；
- 后续的知识冲突和 Skill 生命周期。

### 优先复用

- 飞书用户身份、群聊、卡片、文档和任务；
- 飞书文档和已授权教学平台资料作为教研输入；现有智能会议纪要可用于教研会议；
- 飞书 OpenClaw 插件或 CLI 作为候选执行器；
- Hermes 作为候选通用 Runtime。

飞书中已经存在的官方助手、团队机器人和智能体也可以登记到我们的 Agent 注册表中。注册不等于已经可自动调用：只有具备 API、事件、工作流、MCP、A2A 或 CLI 入口的 Agent 才进入自动适配；只能在界面中聊天的 Agent 暂时标记为人工节点。

### 暂时不做

- 自己做通用会议纪要产品；
- 自己做通用聊天办公助手；
- 自动评分、学生个体画像和未授权的教学平台抓取；
- 一开始同时接入 Hermes 和 OpenClaw；
- 一开始做本地 Agent；
- 把 Laya 放进权限或审批链路；
- Kubernetes、对外多租户和商店分发；
- 复杂 H5 和通用 aPaaS。

## 路线图

### M0：既有能力和官方产品核验（计划书阶段 0）

这是会议试点形成时的能力验证范围；实际完成与未验收项以进度记录为准：

- Hermes 或其他 Runtime 能否被外部受控调用；
- 飞书测试租户能否读取会议产物、接收回调、发送卡片、创建测试任务；
- 官方智能会议纪要是否有可用开放接口；
- 飞书官方 Agent 是否提供 API、MCP、A2A、工作流、事件或 CLI 调用入口；
- 测试租户现有 Agent/机器人能否登记能力、范围、调用入口和责任人；
- 授权音频 ASR 的历史试探；该能力已退出第一版范围；
- Laya 是否有低风险决策收益。

出口：每项都有版本、权限、结果、证据和降级方案。教研转向不追溯改写 M0 证据；第二教学平台的授权和接口另按 T-05 验收。

### M1：最小控制平面（计划书阶段 1）

原阶段使用假 Runtime、假飞书工具和测试数据验证：

```text
Actor → PersonalAssistant → Delegation → TaskRun
                                  ↓
                         Policy → Approval → ToolGateway → Audit
```

必须验证：越权被拒绝、旧审批失效、重复回调不重复执行、失败可恢复、未知结果进入对账。

### M2：既有会议结果落实试点（计划书阶段 2）

既有试点使用飞书会议纪要或文字产物作为输入：

```text
会议产物/录音
→ 待办提取
→ 责任人和范围检查
→ 飞书卡片人工确认
→ 创建飞书任务
→ 通知、审计、对账
```

这一阶段证明会议任务的安全落实，不等于课程计划对齐或集体备课已通过。自有 ASR 已退出第一版范围。

如果官方会议 Agent 有结构化调用接口，优先采用“官方 Agent 产出 + 我们治理落实”的组合；如果只有消息或工作流入口，先做异步适配；如果只能网页人工操作，不做自动化模拟。

### M3：既有可靠性与部署（计划书阶段 3）

既有 outbox、Worker、审批、对账和 Docker Compose 提供可复用基线。持续写入、UNKNOWN 与 Runtime 跨进程恢复等未完成项按进度记录单独验收；业务转向不自动打开线上消息、正式草稿卡片或任务持续写入。

### M4：课程组协作、典型 Agent 和组织治理（计划书阶段 4～5）

先锁定一门样例课程和两名教师，建立课程负责人、资料来源、学期/周次、权限与版本。个人助手委托课程资料 Agent 和教学方案 Agent，完成两类典型任务：课程大纲/周历/教案对齐，以及集体备课建议。每条差异和建议带来源；课程负责人确认教学质量，管理员确认 Agent 权限。复用现有审核官、运维官、灰度、暂停、回退和归档；本地通用样例测试不替代教学业务验收。

### M5：第二平台、反馈、自定义 Agent 与 Skill（计划书阶段 6～7）

选定一个学校可用教学平台，先做真实授权的只读接入及撤权/版本测试；再做脱敏汇总反馈复盘、课程知识引用与冲突复核。两类典型任务通过后，教师可提交自定义 Agent/Skill 草稿，经过独立评测、课程负责人和管理员双确认、建议灰度、回退与归档。仅人工导出文件时只能称跨来源，不能宣称在线跨平台集成。

### 阶段 8：教研工作台与交付

H5 展示课程来源、差异和备课建议、人工审核、版本、运行、Skill 与审计；演示两类典型任务、一次反馈复盘、一个自定义 Agent、第二平台只读来源、越权拒绝、失败对账和回退。实际状态及真实指标只从进度记录和验收报告引用。

### 可选扩展

本地 Agent、OpenClaw 第二 Runtime、A2A 和 Laya，只有在教研主线稳定后再选作扩展。学生个体数据和自动评分不进入第一轮。

## 当前下一步

先完成教研样本和授权准备，再进入 T-01/T-02 的只读实现；已有会议功能继续保留：

1. 与课程负责人或模拟业务方确定一门样例课程、学期、教学目标、两名教师和审定权限；
2. 准备大纲、周历、教案、备课材料与脱敏汇总反馈，区分开发集和独立验收集；
3. 选择第二教学平台，记录其账户授权、课程范围、接口/导出、版本和撤权；
4. 落地 T-01/T-02 课程身份与教学资料只读契约，再做 T-03/T-04 两类典型任务和受控人工确认。

无法取得真实第二平台授权时先完成跨来源教研切片，同时把“跨平台”列为未验收阻塞；最终仍无授权则调整题目和交付声明。线上消息入口、正式 Card 草稿审核和飞书任务持续写入保持原关闭状态，只有独立安全验收后才讨论开启。
