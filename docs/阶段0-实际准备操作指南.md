# 阶段 0 实际准备操作指南

这是一份面向第一次做飞书自建应用的操作顺序。不要一次准备所有东西；先完成第 1 步，再继续第 2 步。当前目标是准备验证环境，不是上线产品。

## 第 1 步：确认飞书账号条件

打开飞书管理后台和开放平台，确认当前账号满足以下至少一项：

- 能进入一个自己可以管理的企业组织；
- 能进入该组织的开放平台开发者后台；
- 能创建“企业自建应用”。

如果只能使用个人账号、不能创建企业自建应用，需要先创建或加入一个自己能管理的测试企业。不要使用学校、实习公司或其他无权管理的企业数据做实验。

这一阶段只需要一个测试企业，不需要购买服务器，也不需要申请商店上架。

## 第 2 步：创建测试应用

在开放平台创建一个企业自建应用，建议名称为：

```text
FDE Agent Phase0 Test
```

如果页面同时显示“从智能体模板开始”，当前请点击“创建企业自建应用”。空白应用便于我们逐项申请最小权限、检查回调和审计边界。之后如果要研究飞书如何预置 OpenClaw/Hermes 接入，可以另建一个临时模板探针应用，不要把模板应用当作主项目控制平面。

记录应用的基本信息，但不要把密钥发到聊天：

- App ID；
- App Secret；
- Encrypt Key；
- Verification Token。

把这些值放在本机密码管理器，或者当前 PowerShell 会话的环境变量中。不要写入 `.md`、`.py`、`.env` 提交文件或截图。

## 第 3 步：只开启第一轮能力

在应用配置中先开启：

1. 机器人能力；
2. 接收群内 `@机器人` 事件；
3. 发送机器人消息；
4. 发送交互卡片；
5. 卡片动作回调；
6. 事件订阅。

在应用详情的“添加应用能力”页面，第一步只点击“机器人”卡片下的“添加”。当前不要添加网页应用、工作台小组件、多维表格插件或原生集成；H5 和其他入口在后续里程碑再配置。添加机器人后先保存，等待下一步配置事件和权限。

机器人配置页中的“允许被其他机器人邀请进群”默认可能开启。第一轮验证必须关闭它：我们只需要用户在测试群内主动 `@` 机器人，不需要机器人互相拉群；开启该选项可能扩大群消息和成员可见范围。

### 3.1 第一轮消息权限

在“权限管理 → 开通权限”窗口，先保持“应用身份权限 `tenant_access_token`”页签，只搜索并勾选以下两项（实际中文名称可能随页面版本略有差异）：

```text
im:message:send_as_bot
im:message.group_at_msg:readonly
```

如果搜索框按中文显示，则分别寻找“以应用身份发送消息”和“接收群聊中 @机器人 的消息”。每次只搜索一个关键词并勾选对应的精确行。不要勾选“读取全部群消息”、批量消息管理或整类分类复选框。

当前先不要切换到“用户身份权限 `user_access_token`”；读取用户可见文档和创建任务会在确认机器人链路后单独申请，并且要按实际业务需要再开。

如果添加机器人后权限列表自动出现其他条目，按第一轮目标清理：保留机器人基本信息读取、`im:message.group_at_msg:readonly` 和 `im:message:send_as_bot`；移除或暂不申请全部群消息、群消息包含机器人、私聊消息读取、群成员读取、机器人菜单读写、机器人互相拉群事件以及视频会议机器人管理等与本轮无关的权限。如果某项被平台标记为能力依赖、无法删除，记录依赖关系，不要用更大的替代权限，并先不要发布应用。

如果测试账号暂时无法将机器人加入群，可以改用单聊作为第一轮事件验证：只额外申请 `im:message.p2p_msg:readonly`（页面中文通常为“读取用户发给机器人的单聊消息”），不要申请读取用户全部私聊。发布新版本并重启长连接后，直接给机器人发送新消息即可；群内 `@` 测试留到后续资源条件具备时再做。

网页应用/H5 可以先开启能力，但暂时不用配置完整页面。第一轮不申请读取全部群消息、删除文档、批量知识库写入等权限。

权限名称在飞书后台可能随版本变化，所以先按“能力”选择，之后把实际审批结果记录下来，不要照抄旧教程中的 scope 名称。

## 第 4 步：准备最小测试资源

只准备虚构数据：

- 测试用户 A：发送 `@机器人`；
- 测试用户 B：作为待办责任人；
- 管理员账号：点击确认按钮；
- 测试群：只加入 A、B 和机器人；
- 测试文档：写一段虚构会议纪要，例如“Alpha 项目周会”；
- 测试任务空间：允许创建一条后删除或归档的任务。

如果暂时只有一个飞书账号，可以先完成应用创建和测试文档准备；真正测试“普通成员不能确认管理员动作”时，再补第二个账号。

## 第 5 步：在本机建立临时目录

使用 PowerShell：

```powershell
New-Item -ItemType Directory -Force D:\FDE-phase0\audio | Out-Null
New-Item -ItemType Directory -Force D:\FDE-phase0\evidence | Out-Null
```

`audio` 放已经授权和脱敏的会议样本，`evidence` 只放脱敏统计、错误类别和远端 ID 的哈希/末尾片段。原始音频和完整文档正文不要复制到项目目录。

## 第 6 步：先运行资源预检

当前不需要填真实值就可以先检查脚本：

```powershell
Set-Location F:\Code_X\FDE学习
py -3.12 scripts\phase0_preflight.py
```

看到 `feishu_status=PENDING` 是正常的，说明还没有把测试凭证放进当前会话。准备好应用后，只在当前 PowerShell 会话中临时设置变量：

```powershell
$env:FEISHU_APP_ID = '<本机填写，不要粘贴到聊天>'
$env:FEISHU_APP_SECRET = '<本机填写>'
$env:FEISHU_ENCRYPT_KEY = '<本机填写>'
$env:FEISHU_VERIFICATION_TOKEN = '<本机填写>'
py -3.12 scripts\phase0_preflight.py --require-feishu
```

预检通过只代表变量存在，不代表飞书权限正确，也不会发起网络请求。

## 第 7 步：回调地址暂缓到最后配置

不要在还没有本地回调服务时随便填写回调地址。等验证脚本或服务准备好后，再用 ngrok、Cloudflare Tunnel 等临时隧道暴露本机端口，并按以下顺序验证：

```text
challenge
→ 签名和 verification token
→ 真实机器人事件
→ 卡片动作回调
```

隧道地址和密钥只用于测试，过期后应撤销。回调验证前不做任何真实写入。

## 第 8 步：音频和 Laya 放到后面

飞书测试资源准备好后，再准备四类授权脱敏音频。Laya 权重、许可证和人工标注样本最后再决定是否准备；没有它们时，会议主流程仍可用规则和 LLM 验证。

## 你现在只需要做什么

当前最小动作是：

1. 确认你能否管理一个飞书测试企业；
2. 创建企业自建应用；
3. 先不要发送任何密钥；
4. 告诉我“能创建应用”或“没有测试企业”。

根据这个结果，再进入下一步，不需要你一次性完成整套准备。
